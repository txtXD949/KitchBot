# Гайд по миграциям БД

Коротко: как безопасно менять схему БД (добавить столбец, индекс и т.п.) без потери данных.

## Что уже настроено

- Инструмент: **yoyo-migrations** (SQL-first, работает поверх `psycopg3`).
- Папка с миграциями: `backend/DBOperations/migrations/sql/`
- Запуск: `python3 -m DBOperations.migrations.db_migrations` из директории `backend/`
- Учёт применённых миграций ведётся автоматически в таблице `_yoyo_migration`, повторно ничего не выполняется.

## Как добавить изменение в схему

### 1. Создать новый `.sql` файл

Имя строго по шаблону: `YYYY_MM_DD_NNN_краткое_описание.sql`

- `YYYY_MM_DD` — дата создания.
- `NNN` — порядковый номер (уникальный, по возрастанию).
- В одном файле — одно логическое изменение.

### 2. Написать SQL

Пример — добавить столбец :

```sql
ALTER TABLE users ADD COLUMN role TEXT DEFAULT 'user';
```

Пример - добавить индекс:
```sql
CREATE INDEX IF NOT EXISTS idx_users_login ON users(login);
```

Правила:

- Где возможно, пишите `IF NOT EXISTS`.

- Не редактируйте уже применённые миграции, только добавляйте новые.

- Не удаляйте данные без согласования. Изменения, ломающие обратную совместимость, обсуждаются отдельно.

### 3. Применить
```bash
cd backend/
python3 -m DBOperations.migrations.db_migrations
```

yoyo применит только новые файлы, которых ещё нет в `_yoyo_migration`. Всё выполняется в транзакции: при ошибке изменения откатятся.
